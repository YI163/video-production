# 03 · 视频制作 Workflow（可复用版）

> 来源：一个真实的 45–60s 竖屏 vlog 案例与一次失败修改的对照（均已匿名，不含素材/人物/机构信息）。
> 目标：让“高质量成片”更可重复，同时保留创意判断空间；不是把已批准版的镜头/滤镜固化成模板。
> 配套：`case-study.md`（为什么）、`modification-protection.md`（改片）、`../SKILL.md`（Agent Skill）。

---

## 0. 先分类：新制作 / 局部修改 / 全量重做

| 类型 | 判定 | 处理 |
|---|---|---|
| 新制作 | 新需求/新素材/新主题 | 走完整 7 阶段 |
| 局部修改 | 只改字幕/标题/几处包装/一段 B-roll/音量，镜头结构与视觉系统不变 | 走“最小 diff + A/B + 复核”，见修改规范 |
| 全量重做 | 换全部素材、换画幅/布局/风格、重写叙事 | 当成新制作；**不能**用局部补丁流程 |

**硬规则：** 用户说“所有素材都换/重新来”，即使语气是“小瑕疵”，也按全量重做处理；否则素材条件、构图、颜色、节奏的假设全部失效。

---

## 1. Intake（需求理解与创意构思）

### 1.1 最小澄清清单

不需要一次问十个问题；用户已给的信息不要重复问。只补影响交付的缺口：

- 平台/用途：抖音/小红书/视频号/YouTube Shorts/内部汇报？决定时长、安全区、字幕风格。
- 目标时长：15s / 30s / 45–60s / 90s；没有就说建议值。
- 画幅：9:16 竖屏（默认）/ 1:1 / 16:9；本次默认竖屏。
- 语言/字幕：简体中文、是否需要双语、是否烧录 + SRT。
- 素材：文件路径、是否 Log/HLG、是否有口播、是否有版权限制。
- 音乐：用户提供/CC0/CC BY/无 BGM；若 CC BY，片尾或交付说明必须署名。
- 交付：目录/文件名/是否覆盖旧版；桌面交付是否需要权限。
- 不可改项：旧版的视觉系统、事实、品牌、已认可的部分。

### 1.2 产出

`docs/00-brief.md`（或复用 `00-制作总则与环境.md`）至少包含：

- 一句话目标 / 目标观众 / 平台 / 时长 / 画幅；
- 素材清单（路径、时长、分辨率、帧率、Log/Rec709、音频）；
- 事实基线（可上屏 / 只可字幕 / 不可用）；
- 视觉方向（卡片/满屏/混合；标题/字幕/事实卡/片尾）；
- 声音方向（人声/BGM/环境声/音效）；
- 质量红线（黑帧、变形、遮挡、事实错误、未授权音乐）；
- 审核方式（谁审、审什么、什么算 pass）。

**为什么先写：** 已批准版的 `00-制作总则` 让 4 个角色对同一组约束负责；没有它，后面每个角色都会“自由发挥”。

---

### 1.3 Reference study（新制作 / 全量重做）

在锁定视觉系统、写分镜之前，先研究 **3–5 个同平台/同类型/同时长段** 的优秀 vlog。不是“看个感觉”，而是拆：

- 前 1–3 秒钩子：画面 / 文案 / 声音；
- 结构：镜头数、平均镜头时长、A-roll/B-roll 比例、事实卡/片尾位置；
- 包装：标题层级、字幕字号/位置、色彩、转场、信息密度；
- 声音：人声、BGM、音效、环境声；
- 为什么有效（一句话）；
- **可迁移原则 vs 表面元素**。

产出 `reference-study.md`：3 条要采用的原则、2 条要避免的坑、2–3 个创意选项 + 推荐。不要逐镜照搬、不要复制人脸/音乐/版权素材。局部修改可跳过，除非用户要求。

**Gate：** 新制作/全量重做没有 reference study，不锁视觉系统、不写最终分镜。

## 2. Material audit（素材准备与研究）

### 2.1 技术盘点

```bash
FF=tools/ffmpeg
for f in clips/*.mp4; do
  echo "== $f"
  $FF -hide_banner -i "$f" 2>&1 | grep -E 'Duration|Stream|color|transfer|primaries'
done
```

记录：时长、分辨率、帧率、编码、位深、色彩标记、音频声道/采样率、码率。
**Log/HLG 识别：** 画面低对比/低饱和 + 10-bit + 相机 Log 标记；不要假设“看起来灰”就一定是 Log，也不要假设“标记 bt709”就一定不是 Log（DJI 常见）。

### 2.2 画面证据

- 每段 1s 接触表：`fps=1,scale=... ,tile=...`；
- 关键帧：开头/结尾/人物入画/动作/转场/构图变化；
- 记录：人物位置、logo/背景、抖动、曝光、白平衡、可用入出点、弃用理由。

### 2.3 声音/逐字稿

- 提取 16k mono WAV；
- Whisper.cpp base 先出草稿，再用更强模型/多模型交叉复核（有缓存则 faster-whisper medium；没有则人工按语义修正）；
- **B/C/D 的环境声不要强行配字幕**；Whisper 在低电平噪声上会幻觉；
- 逐字稿必须带 0.1s 级时间码；不确定词标注，不假装 100% 确定。

### 2.4 可用区间表

| 区间 | 源入 | 源出 | 时长 | 内容 | 用途 | 风险 |
|---|---|---|---|---|---|---|

**Gate：** 素材报告必须能被审核员独立抽帧复核；每个“可用”区间有证据；每个“不可用”有理由。

## 3. Creative system + script（方案与脚本）

### 3.1 先定视觉语法，不要先堆镜头

**A 段（口播/人物）适配决策：**

| 条件 | 优先方案 | 理由 |
|---|---|---|
| 横屏 4:3/16:9，分辨率 ≤1080p，需要保留环境/logo | **卡片式**（4:3/16:9 画布 + 标题 + 字幕） | 避免 2.67× 放大；保留信息；竖屏阅读习惯 |
| 原生 4K 竖屏，人物 headroom 足够 | **满屏** | 画质最好、最像原生竖屏 |
| 横屏 4K，人物居中、背景可裁 | 满屏裁切 + 安全构图测试 | 4K 细节足够；必须验证头顶/手势/logo |
| 横屏但人物/背景都重要 | 混合：主镜头卡片，关键句短暂满屏/推近 | 兼顾信息与动感 |

**不要因为“上次用了卡片”就永远卡片；也不要因为“4K”就默认满屏。用样片 + 构图测试 + 审核决定。**

### 3.2 视觉系统清单

- 画布：1080×1920，30fps，yuv420p；
- 安全区：顶部 ≥220px 不放关键信息；底部字幕底边 ≥200px（建议 ≥240px）；右侧平台操作列留空；
- 标题：主标题/英文/地点，字号/位置/出现时间；
- 字幕：字体、字号、描边/底衬、每行 ≤14 字、每条 ≤2 行；
- 事实卡：面板、主数字、辅助说明、来源（用户要求删就删，但不要留下空洞）；
- 片尾：校名/英文/地址/地点/落点/署名（按用户要求增减）；
- 转场：硬切为主，关键段落 0.2–0.4s 叠化；
- 调色：Log→Rec709 的 LUT/手动曲线/白平衡；同场景镜头要匹配。
- 事实卡底图：连续卡片用不同源区间；避免 1s 以上重叠/几乎一样的镜头；运动镜头在卡后减速或定格。
- 桥段：最后一张事实卡到片尾之间，每个 2–3s 画面必须有标题/口播/地点/叙事功能；否则缩短或删除，不能留无字无声“空隙”。

### 3.3 脚本必须“可剪”

每个镜头至少：

```
镜号 | 成片入出 | 时长 | 源素材 | 源入出 | 画面处理 | 字幕 | 包装字 | 转场 | 声音
```

- 逐镜时长求和 = 目标总时长；
- A 段音频与画面按偏移逐帧对齐（例：成片 = 源 + 4.0s）；
- 字幕用成片时间码，不用源时间码直接烧；
- 钩子在前 3 秒；每 2–4 秒有画面变化或信息推进；
- 事实卡/片尾的每一行文案都有来源/风险标注。

**Gate：** 脚本审核员要能抽帧核对源入出点、读 SRT 核对字幕、算总时长；不能只看文字。

## 4. Asset build（素材准备与生成）

### 4.1 调色

- 有官方 LUT 用 LUT（如 DJI D-Log M → Rec709）；没有则手动：
  - `colorlevels`/`curves` 拉伸对比；
  - `eq` 调整 gamma/饱和；
  - `vibrance` 提升低饱和；
  - `colorbalance` 校正冷暖；
  - 轻 `unsharp`；避免过度锐化白墙。
- **先做 3–5 张对比样片**（人脸/白墙/品牌色/天空），确认肤色与白平衡，再批量。
- 10-bit 素材先转 8-bit 再做某些 `colorlevels`（本机 ffmpeg 8 实测 10-bit 下 `colorlevels` 可能输出黑帧；加 `format=yuv420p` 解决）。
- 同场景镜头用同一组参数；不同场景可微调，但要并排对比。

### 4.2 包装/字幕

- 用 Pillow 生成全画布 RGBA PNG（标题/事实卡/片尾/字幕条），避免 libass 字体/排版不可控；
- 字幕 54px 白字 + 7px 黑描边 + 轻投影；底部安全区；
- 事实卡面板不透明/半透明要实测：背景文字不能透出干扰；
- 片尾文字不要压在复杂背景上；必要时加渐变/压暗。

### 4.3 声音

- 人声：高通 80–90Hz、轻降噪、2:1 压缩、loudnorm 到口播段合适电平；
- BGM：先测原曲响度，再压到人声下方 12–18dB；片头淡入 1–1.5s、片尾淡出 2–3s；
- 环境声：B/C/D 可静音或压到 −35dB 以下；不要用噪声当“氛围”；
- 整体：−16 LUFS ±2，真峰值 ≤ −1dBTP；用 `check_video.py` / `ebur128` 复测。

### 4.4 工程化

- 逐镜渲染为独立 MP4，再 concat/xfade；不要一个巨型 filter_complex 赌全部；
- 中间文件保留（shots/segments/overlays/audio），便于局部重做；
- 所有参数写进 剪辑说明文档 或脚本常量；
- 版本化：`v1`、`v2`、`approved`；不覆盖母版。

## 5. Review / QC（预览、检查与质量评估）

### 5.1 两类审核，不能互相替代

| 类型 | 谁做 | 看什么 | 输出 |
|---|---|---|---|
| 技术质检 | 技术/分析员 | 分辨率、帧率、编码、时长、响度、TP、黑帧、解码、字幕烧录、安全区 | 技术质检报告 + JSON + 抽帧 |
| 内容/观感审核 | 独立审核员 | 钩子、叙事、节奏、构图、调色、转场、包装、字幕准确性/同步/排版、事实 | 成片审核报告 + verdict + findings |

**技术质检通过 ≠ 观感通过。** 已批准版与修改版 的技术都过，但用户仍不满意；反之，技术失败一定不能交付。

### 5.2 审核方法

- 全片 1s contact sheet + 剪辑点/字幕点补帧；
- 每个事实卡/片尾卡抽 1–2 帧；
- 读 SRT，对照逐字稿和抽帧；
- 抽听/看波形：响度、爆音、BGM 比例；
- 事实核查：官方来源/字幕口径/“仅讲述者观点”；
- 问题必须带时间码、现象、修改建议、严重级别（blocker/high/medium/low）。

### 5.3 Gate 规则

- 有 blocker/high → 不交付；
- medium 若影响观感/信息 → 修完再复核；
- low 可记录后交付，但不能用“low”掩盖用户明确指出的问题；
- 审核员 pass 后，若又改了任何画面/字幕/音频，必须重新复核受影响部分。

## 6. Deliver（最终输出与成果交付）

### 6.1 交付包

```
deliverable/
  <name>.mp4            终版（H.264/AAC，faststart）
  <name>.srt            外挂字幕（与烧录一致）
  <name>_封面.jpg        1080×1920
  交付说明.md            规格/来源/CC BY/审核结论/已知限制
  checksums.sha256
  approved/               只读已批准版本（如为修改任务）
```

### 6.2 交付前检查

- 文件名/路径符合用户要求；
- 终版与已审版本一致（流拷贝/同参数重编码）；MD5/SHA256 记录；
- `check_video.py` 通过；QuickTime/手机可播；
- SRT UTF-8，条目与成片一致；
- 封面/交付说明齐全；
- 桌面拷贝权限已处理；不覆盖唯一已批准版。

### 6.3 交付说明必须写

- 规格/时长/文件清单/MD5；
- 素材来源、创作结构、字幕、BGM 与 CC BY；
- 事实来源；
- 已知限制（低置信字幕、软化、静态片尾等）；
- 审核结论引用。

## 7. Revision（修改与版本管理）

**完整规范见 `modification-protection.md`，本节只给流程：**

1. 冻结当前满意版本（只读副本 + checksum）；
2. 把用户要求逐条写成 change list（请求改/未请求改）；
3. 判定局部/全量；全量换素材按新制作；
4. 最小 diff；能只改 PNG/SRT/音频就不要重渲全片；
5. A/B 对比：旧 vs 新，同语义时间点、同技术指标、同字幕；
6. 独立复核；不通过回滚；
7. 版本化交付，绝不覆盖唯一已批准版。

## 8. 角色与协作（AgentTeams 或单人）

### 8.1 什么时候值得上团队

- 素材多、审核要求高、需要脚本/剪辑/审核分离；
- 用户明确要求“每一步审核”；
- 交付周期允许 2–4 小时。

### 8.2 最小角色

| 角色 | 职责 |
|---|---|
| Captain | 需求、计划、裁决、最终交付；不替审核员下 pass |
| Analyst | 素材/逐字稿/技术质检 |
| Writer | 脚本/字幕/包装文案 |
| Editor | 调色/剪辑/混音/打包 |
| Reviewer | 独立抽帧/读 SRT/事实核查；verdict |

### 8.3 单人也要保留“独立审核”

即使不上团队，也要在交付前做一次“换视角审核”：隔一段时间重新看全片、抽帧、读 SRT、跑 checker；不要边剪边自评。

## 9. 失败模式清单（按历史教训）

| 失败模式 | 症状 | 预防 |
|---|---|---|
| 把全量重做当局部修改 | 换全部素材/风格，但没重走研究/脚本/审核 | 先分类；全量=新制作 |
| 未经要求改视觉系统 | 卡片→满屏、标题消失、构图变紧 | 未要求不改；改前样片+审核 |
| 调色无参考 | 肤色不一致、镜头跳色、过饱和/发灰 | LUT/参考帧/同场景对比 |
| 只看技术指标 | checker 过但观感差 | 独立观感审核 + A/B |
| 包装删减后留白 | 事实卡/片尾变空 | 删内容后重排层级/留白 |
| 审核被中断 | 无 verdict 就交付 | 没有 pass 不交付；记录中断 |
| 覆盖唯一好版本 | 失败后无法回滚 | approved 只读 + checksum |
| 素材时间码错 | 声画错位/翻页错 | 脚本带源/成片双时间码；审核抽帧 |

## 10. 交付标准（Definition of Done）

- [ ] 成片 1080×1920 / 30fps / 目标时长；H.264/AAC 可播；
- [ ] 字幕烧录 + SRT；13/13 或全覆盖；无错字/漏句/遮挡；
- [ ] 响度 −16±2 LUFS，TP ≤ −1dBTP；无爆音；BGM 淡入淡出；
- [ ] 0 黑帧（非设计）；无变形/拉伸；A 段适配安全；
- [ ] 事实/来源/版权/CC BY 正确；
- [ ] 独立审核 verdict=pass（或用户明确接受 low）；
- [ ] 交付包 + 交付说明 + checksums；
- [ ] 已批准版本/母版只读保留。
