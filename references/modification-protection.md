# 04 · 视频修改与质量保护规范

> 适用：用户对“已经满意/已交付”的视频提出修改；或对已批准版本做二次编辑。
> 目标：不因局部修改毁掉整体；失败可回滚；绝不覆盖唯一成功版本。
> 来源：一个真实项目的成功链 + 一次“把全量重做当局部修改”的失败对照（已匿名）。

---

## 0. 七条硬规则（先记住）

1. **修改前先保存当前满意版本**：只读副本 + SHA-256 + 版本名（approved/v1/v2）。
2. **明确用户要求修改的部分**：逐条写成 change list；请求改的 ≠ 可以顺手改的。
3. **未经要求修改的部分默认保留**：视觉系统、构图、调色、字幕样式、包装位置、音乐、节奏。
4. **优先最小范围、可回退的修改**：能只改 PNG/SRT/音频/单镜，就不要重渲全片。
5. **无法真正局部修改时，先识别重生成风险**：换全部素材/换布局/换调色 = 新制作，必须走完整流程。
6. **修改后比较新旧版本**：同语义时间点抽帧、同技术指标、同字幕；重点看“没要求改的部分有没有退化”。
7. **绝不因修改失败而覆盖唯一成功版本**：approved 只读；新版不过审就回滚，不删除旧版。

> 一句话：**改的是“点”，守的是“面”。** 用户只授权你改点，不等于授权你重做整个视觉系统。

---

## 1. 修改前：冻结与分类

### 1.1 冻结（必须做）

```bash
mkdir -p revisions/approved
cp -p deliverable/<name>.mp4 revisions/approved/<name>_approved.mp4
cp -p deliverable/<name>.srt revisions/approved/<name>_approved.srt
cp -p deliverable/<name>_封面.jpg revisions/approved/<name>_approved_封面.jpg
shasum -a 256 revisions/approved/* > revisions/approved/checksums.sha256
chmod -R a-w revisions/approved   # 至少不要在工作流里误写
```

同时保存：当前使用的脚本、overlay PNG、SRT、build 参数、审核文档、交付说明。**不要**用 `mv` 把 approved 移走；用副本。

### 1.2 把要求拆成 change list

| # | 用户原话 | 改什么 | 类型 | 是否请求 |
|---|---|---|---|---|
| 1 | 音乐淡入淡出 | BGM 包络 | 音频 | 是 |
| 2 | 开头 2426 | 钩子镜头/文字 | 内容 | 是 |
| 3 | 删嘉宾观点 | 一个 overlay | 包装 | 是 |
| 4 | 换全部素材/调色 | 素材/调色/A 段 | 全量 | 是（但等于重做） |
| 5 | 删来源行 | 事实卡 PNG | 包装 | 是 |
| 6 | 删片尾两行 | 片尾 PNG | 包装 | 是 |

**分类规则：**

- 只改文字/颜色/音量/一个 overlay → 局部；
- 改一段 B-roll/一个镜头 → 局部（但需检查声画/字幕）；
- 换画幅/布局/视觉系统/调色管线 → 结构性修改；
- 换全部素材/重写叙事 → **新制作**，不是修改。

### 1.3 影响面（blast radius）评估

| 改动 | 可能连带影响 |
|---|---|
| 换 A 段素材 | 构图/清晰度/声画同步/字幕安全区/标题位置/节奏 |
| 换全部素材 | 素材可用区间、镜头顺序、调色、B-roll、事实卡底图、片尾 |
| 改字幕 | 断句/时间码/遮挡/字号/行数 |
| 改 BGM | 人声清晰度/响度/淡入淡出/版权署名 |
| 改事实卡/片尾 | 安全区/信息层级/留白/字号/来源 |
| 改画幅/布局 | 所有 overlay 坐标、所有字幕安全区、所有镜头构图 |

> 影响面跨 2 个以上系统（画面/字幕/声音/包装）时，默认按“结构性修改”处理，必须重新审核受影响的全部系统。

---

## 2. 最小 diff 策略

### 2.1 能只改一层，就不要重渲全片

| 需求 | 最小做法 | 不要做 |
|---|---|---|
| 改一个字幕 | 改 SRT/字幕 PNG，重新 overlay 字幕层 | 重剪所有镜头 |
| 删/加一个角标 | 改 overlay PNG，重新 overlay | 重调色/重剪 |
| 改 BGM/淡入淡出 | 重混音轨，视频流拷贝 | 重渲视频 |
| 改一段 B-roll | 只重渲该镜，重新拼接受影响段 | 全片重剪 |
| 改调色 | 只重渲受影响镜头，保留剪辑/字幕/音频 | 重写脚本/重剪结构 |
| 删事实卡来源/片尾行 | 改对应 PNG，重新 overlay | 重做整张卡/整段片尾 |
| 换全部素材 | **新制作**：重研究/重脚本/重调色/重审核 | 在旧工程上局部替换 |

### 2.2 局部修改后的“受影响系统”清单

- 画面：构图、清晰度、色彩、稳定性、转场；
- 字幕：时间码、断句、遮挡、字号、行数；
- 声音：人声/BGM/音效、淡入淡出、响度；
- 包装：标题/事实卡/片尾/角标、安全区；
- 事实：来源、口径、日期、数字；
- 技术：分辨率/帧率/编码/黑帧/解码。

**只改一个系统，也要检查它与其它系统的接口。** 例：改字幕断句可能改变行数/遮挡；改 BGM 可能改变人声清晰度。

---

## 3. 全量重做：必须按新制作走

以下任一条件成立，判定“全量重做”：

- 用户提供全部/大部分新素材，要求“不要用之前的”；
- 画幅/布局/视觉系统改变；
- 调色管线改变（Rec709 → Log/HLG，或反之）；
- 叙事结构/镜头数大幅变化；
- 目标时长/平台改变。

**处理：**

1. 保留 approved 作为参考，不覆盖；
2. 重新写 brief/visual system/script；
3. 重新做素材研究（新素材的可用区间、构图、颜色、声音）；
4. 重新调色（LUT/参考帧/同场景匹配）；
5. 重新走独立审核（技术 + 观感 + 字幕 + 事实）；
6. 交付新版，approved 保留。

**不要：** 在旧脚本上把镜头路径替换成新素材就直接渲染；旧脚本的源时间码、构图、字幕、B-roll 逻辑全部可能失效。

---

## 4. A/B 对比协议（修改后必做）

### 4.1 抽帧点

至少覆盖：

- 开头 0–2s（钩子）；
- A 段/人物第一次出现；
- 每个 B-roll 段落各 1 帧；
- 每张事实卡 1 帧；
- 片尾卡 2 帧；
- 任何“用户特别在意”的点（开头/结尾/字幕/品牌）。

**方法：** 同一语义时间点（不是同一绝对秒数，因为时长可能变）各抽一帧，左右并排；标注版本/时间码。

### 4.2 必比项

| 项 | 检查 |
|---|---|
| 构图 | 人物头顶/手势/logo/背景是否被裁；主体是否过小/过大 |
| 调色 | 肤色/白平衡/对比/饱和/镜头间一致性 |
| 字幕 | 文案/断句/行数/字号/安全区/遮挡/同步 |
| 包装 | 标题/事实卡/片尾/角标位置/留白/信息层级 |
| 节奏 | 镜头数/时长/转场/信息密度 |
| 声音 | 人声清晰度/BGM 比例/淡入淡出/爆音 |
| 技术 | 分辨率/帧率/编码/LUFS/TP/黑帧/解码 |

### 4.3 量化辅助

- 未改动镜头：抽帧 PSNR/SSIM 或帧哈希，确认没被“顺手重渲”改变；
- 字幕：SRT 逐条 diff；烧录抽帧 OCR/目检；
- 音频：整体/分段 LUFS、TP、BGM 段电平；
- 技术：`check_video.py` 前后对比。

> PSNR/SSIM 只证明“像素接近”，不能证明“更好看”；它们是**回归检测**，不是审美判断。

---

## 5. 审核与回滚

### 5.1 修改后审核

- 独立审核员（不是改片的人）抽帧/读 SRT/听音频；
- 重点检查：请求改的是否改对；**未请求改的是否退化**；
- verdict=pass 才交付；needs_revision 修完再复核；
- 如果修改只影响字幕/包装，可做“轻量复核”，但仍需独立。

### 5.2 回滚

- 新版不过审 → 保留新版为 `revN_rejected`，恢复 approved 到交付位置；
- 不删除 approved；不覆盖唯一成功版本；
- 记录失败原因/证据，供下一轮参考。

### 5.3 版本命名

```
deliverable/
  <name>.mp4                 # 当前交付（只指向已过审版本）
  revisions/
    approved/<name>_approved.mp4 # 只读
    v1/<name>_v1.mp4
    v2/<name>_v2.mp4
    修改版/<name>_修改版_rejected.mp4
    checksums.sha256
```

- 当前交付文件可以用 `cp` 覆盖，但 `revisions/approved` 永远只读；
- 每次交付写 `交付说明.md` + checksum；
- 用户明确要“保留旧版”时，桌面同时保留 `_v1` 命名。

## 6. 本次失败的具体教训

| 教训 | 证据 | 以后怎么做 |
|---|---|---|
| 全量换素材被当成局部修改 | 用户要求换全部素材；修改版重写了镜头，但未重走完整审核 | 先分类；全量=新制作 |
| 未经要求改 A 段布局 | 已批准版 4:3 卡片 + 标题；修改版 4K 满屏裁切 | 未要求不改；改前样片+审核 |
| 调色无参考/无审核 | 旧素材 Rec709；新素材 D-Log M 手动调色 | LUT/参考帧/同场景对比/独立看色 |
| 独立审核中断 | 23:49 subagent 被停止，无 verdict | 没 pass 不交付；记录中断 |
| 无 A/B 对比 | 交付前只跑 checker | 交付前并排抽帧对比 |
| 包装删减后留白 | 事实卡/片尾删来源/两行后变空 | 删内容后重排层级/留白 |

## 7. 修改验收清单（打勾）

- [ ] approved 已冻结 + checksum；
- [ ] change list 已逐条确认（请求/未请求）；
- [ ] 影响面评估完成；
- [ ] 采用最小 diff（或明确判定全量重做）；
- [ ] 未请求改的部分有对比证据未退化；
- [ ] 字幕/SRT/安全区复核；
- [ ] 声音/响度/BGM 淡入淡出复核；
- [ ] 技术 checker 通过；
- [ ] 独立审核 verdict=pass；
- [ ] 版本命名/交付说明/checksum 完成；
- [ ] approved 未被覆盖；回滚路径可用。
